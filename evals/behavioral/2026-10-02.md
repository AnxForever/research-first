# research-first：2026-10-02 实际任务评估

本轮目标是让研究改善最终成品：理解简短需求中的实际目的，发现值得补充的问题，判断现有方案能否复用，并把重要发现落实到实现和验收中。

在本次快捷导航任务里，第一版修订指令下的实现主动发现并修复了“关闭搜索后键盘焦点丢失”；无 skill 和已发布版的实现都遗漏了这个问题。独立浏览器验收分别为 **9/10、9/10、10/10**。另一项保存常用视图任务的完整流程、存储损坏、写入失败三组场景也通过。这是具体任务中有用的改进证据，尚不是普遍成功率提升的证明。

## 本轮修改

1. **减少无谓确认。** 普通实现请求已经包含现有技术栈、既定范围内的常规可逆选型；展示方案后继续完成。研究专用请求、明确要求等待、改变产品目的或超出范围的外部承诺仍保留边界。
2. **检查实际接入。** 从组件文档继续追到项目封装和调用链，区分组件提供的能力与应用仍需承担的状态、焦点、持久化、清理和失败恢复。
3. **验收完整使用过程。** 将“键盘支持”“保存成功”等笼统声明改成能观察的结果：进入、操作、退出、返回；保存、刷新、恢复；失败时的实际反馈。

这些是通用工作原则。模态框和存储是解释原则的例子，其他任务只执行与承诺结果有关的检查；没有新增强制全项目检查表。

A、B、C 的实现请求相同，评价者对三个产物使用同一套校准后的浏览器检查；未向实现者提供缺陷或参考答案。C 在其实现完成前没有收到 A/B 的验收结果。保存视图任务没有“你可以自主选型”的额外授权句，也完成了常规选型和实现。

导航十项为：快捷键打开、方向键和回车、同名页面的上下文与路由、Escape 后焦点恢复、重新打开、无结果状态、既有主题切换、手机点按、390×844 视口布局、运行时错误。路由跳转后复用仍单独检查过；十项不是全部键盘或无障碍规范的穷尽测试。

保存视图的三组结果覆盖：命名保存和恢复实际筛选、刷新后重选、重复名称拒绝、删除后刷新仍消失；损坏该功能的存储值后页面可用；只对该功能的写入注入失败时显示错误且不假报成功。持久化字段限定为 `id/name/search/status/priority`，未保存业务行或勾选状态。当前实现支持删除，不支持直接编辑已有视图名称。

最终指令另做 D 诊断：把 B 的代码交给新上下文，要求检查已有快捷导航的完整键盘和手机体验，没有告知具体缺陷。实现者修复了输入框内快捷键抢焦点、关闭后的焦点恢复，以及 320px 窄屏弹窗越界；其定向 Edge 脚本覆盖 390×844、390×430、320×568。随后独立评价者对 D 运行公开目录的最终脚本，**10/10 通过**，并另行确认 Escape 后入口复焦。三个尺寸的完整检查属于实现者保留的可复跑记录，独立统一验收只覆盖其中的 390×844。

D 的任务是修复已有实现，与 A/B/C 的实现任务不同，也使用了后来改进的验收脚本，因此单独解释。该工作上下文开始时曾读取任务相关历史记忆，之后没有继续读取；未提供本次 A/B/C 结果或缺陷答案，不将 D 称为完全隔离试验。

## 研究如何改变成品

导航沿用已经安装的 cmdk、Radix Dialog 和现有路由目录，没有引入新依赖。关键问题出在接入方式：项目的打开按钮没有通过 Radix 的 Trigger 关联，组件默认的关闭处理无法自动找到该按钮。C 检查实际焦点后补上应用侧恢复逻辑，并在跳转后处理原入口已卸载的情况。

这符合 [WAI-ARIA 模态对话框模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)对退出后返回调用入口或合理后续位置的说明。读到组件支持键盘操作，只能支持候选判断；组装后的行为仍需实测。

保存视图沿用现有 TanStack Table 与 URL 筛选状态，用浏览器存储保存命名预设。实现者查阅了 [Linear Custom Views](https://linear.app/docs/custom-views)、[TanStack Table 状态说明](https://tanstack.com/table/v8/docs/framework/react/guide/table-state)与 [MDN localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage)，将现有筛选的来源、预设的保存范围和存储失败行为落实到了代码与检查中。

## 校准记录与限制

早期验收脚本出现过定位和时序错误：默认选中第一项后按向下键会选择下一项；冷启动需要等待控件挂载；主题变更早于关闭动画完成；筛选选项名称带计数；用户主动换了筛选之后，不能仍断言旧视图处于激活状态。已修正这些测试假设，再运行对应检查。原始失败与修正记录保留在本次本地评估目录，没有算作产品失败。

公开的导航脚本在复制后进一步改成搜索指定主题并等待对话框完全关闭，以避开定位和动画竞争；它不是原始 A/B/C 检查脚本的逐字副本。原始三份独立结果仍保留，复跑结果另列。A/B 的焦点丢失还经过独立、稳定等待后的检查确认。

分发前又将导航脚本限制为本地同源请求，并拒绝带凭据的 URL。由此主动拦截的既有字体、演示头像会产生资源加载错误；脚本保留精确被拦截 URL 和对应错误，另列为测试环境结果，不当作应用异常。未按通用错误文本批量忽略本地错误。此版本再跑导航仍为 10/10。

第一版修订与当前最终指令需区分：C 和保存视图使用的 `SKILL.md` SHA-256 为 `3375b9b3e319f1f6b43524bdbeed7e31c7ba7bf40bb104c7fc5c4a45be433db5`。其后依据遗漏情况补充了可观察验收的例子，当前入口 SHA-256 为 `3cf8d0ac2d5616cd387773806fe94b564c0434c5de5a71b417efe1b1fae6b50a`。最终指令另做已有实现的诊断测试，不能把它与前三次完全相同任务混算。

本轮每种条件只有一次实现，允许正常使用其他适用 skill。请求的模型配置相同，但宿主没有提供可确认的实际模型 ID、完整用量和原始工具轨迹；实现者笔记不能替代原始轨迹。后续样本获得了前期发现的本地 pnpm 环境提示，不做时间或费用优劣比较。C 一次误搜父目录时看到了相邻样本的 pnpm 配置路径和首行；报告未读取相邻实现或结果，因此也不宣称完全盲测与严格隔离。

浏览器验证为 Windows 上的 Edge，手机部分为触屏和视口模拟，没有验证真实手机、其他浏览器或所有无障碍要求。这里显式加载 skill；安装可被发现、宿主自动触发、触发后的效果是不同问题，本轮没有证明自动触发。

维护检查方面，包结构与本地 Markdown 链接校验、skill-creator 的基础校验均通过；单元测试共运行 32 项，30 项通过、2 项因当前 Python 未安装可选 SDK 而跳过，0 项失败。未把跳过的 SDK 合约检查计为通过，也未调用真实 Jev API。这些检查验证包和工具基础质量，不计入上面的用户体验结果。

这些限制决定了本轮可得出的结论：新增规则帮助一次实现发现了实际缺陷，另一类任务也能完成有效交付；后续仍需在不同项目与重复试验中积累证据。评估方法依据[代理评估指南](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)区分产物结果、执行记录和多次试验，不用文档篇幅或搜索次数代替质量。
